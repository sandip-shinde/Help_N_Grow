🌱 Help N Grow – Technical Documentation

Economic Help and Growth Center – A multilevel membership & help platform built with ASP.NET Core MVC.

Members join under a parent, pay a help amount to their parent and a service fee to the company, then grow through levels as their sub-members complete transactions.

🏗 ASP.NET Core MVC 🗄 SQL Server / EF Core 🔐 Cookie Auth 📄 PdfSharpCore PDF 👥 3 Roles 4 Core Tables
📋 Project Overview

Help N Grow is a web-based multilevel membership platform where people join under a sponsor (parent) member, contribute a fixed help amount directly to their parent member's bank account and a service fee to the company, and in turn receive help from new members they recruit.


The platform manages three user roles, multiple packages, nine progression levels, and all financial transactions with photo proof upload and admin approval workflows.

🔄 Functional Flows

Flow 1 — Admin Login

Admin Super Admin GET /Home/AdminIndex POST /Home/AdminIndex

  1. User navigates to /Home/AdminIndex → Existing session is cleared (AdminLogout called)
  2. User enters Username, Password, and selects Role (Admin / Super_Admin)
  3. POST is sent; server validates that all three fields are non-empty
  4. AuthenticateLogin.AuthenticateUser() queries Registration table with Is_Active=true
  5. On success → TempData is populated: Package_ID, Package_Name, Level_Id, Parent_Id, username
  6. Cookie authentication principal is signed in
  7. If Role = Admin → Redirect to AllMember
  8. If Role = Super_Admin → Redirect to TransactionApprovalIndex
  9. On failure → View returned with error message "Please check Username and Password"

Flow 2 — Super Admin Dashboard & Transaction Approval

Super Admin

  1. Super Admin logs in → Directed to TransactionApprovalIndex
  2. Sees list of all transactions with member details, amounts, receipt thumbnails
  3. Can filter by member name, transaction number, date, package
  4. Clicks View Photo → Retrieves VARBINARY image from DB via ViewCompanyPhoto / ViewMemberPhoto
  5. Clicks Approve → TransactionApprovalEdit sets Is_Approved = true
  6. On approval, member's Is_Active is set to true in Registration table
  7. Level upgrade check is triggered for the parent member
  8. Super Admin can also view Admin Reports by Package / Package+Level / Package+Level+Member

Flow 3 — Member / User Login

User / Member GET /Home/Index POST /Home/Index

  1. User navigates to /Home/Index → Session cleared (Logout called)
  2. User enters Username, Password, Role (User / Member)
  3. AuthenticateLogin.AuthenticateUser() validates credentials with Is_Active = true
  4. On success → TempData loaded (Package_ID, Package_Name, Level_Id, Parent_Id, username)
  5. Cookie principal signed in
  6. Level record fetched for current Level_Id + Package_ID
  7. Level_Upgrade() private method is called → shows congratulation message if promoted
  8. Redirected to Dashboard view with Level details (Amount displayed)
  9. On failure → "Please check Username and Password"

Flow 4 — New Member Registration (by Parent Member)

Member GET /Home/RegistrationCreate POST /Home/RegistrationCreate

  1. Logged-in member navigates to RegistrationIndex to see their sub-members
  2. Member count checked against Level.MemberCount to decide if "Create" button is shown
  3. Member clicks Add New Member → RegistrationCreate GET loads parent's bank/UPI details for display
  4. New member fills: Full Name, Mobile, Bank AC, IFSC, UPI ID, Username, Password and accepts Terms & Conditions
  5. POST validates: Username uniqueness checked in DB
  6. New member inherits: Package_ID, Package_Name, Level_Id from parent; Is_Active = false
  7. Record saved → Redirect to RegistrationIndex
  8. Transaction upload is prompted to activate membership

Flow 5 — Existing Member Level Upgrade (Add Old Member)

Member GET /Home/RegistrationOld

  1. On RegistrationIndex, existing sub-members (previous level) are listed in an "Old Members" dropdown
  2. Member selects an existing member's unique ID and clicks Add Existing
  3. RegistrationOld verifies member belongs to parent (Parent_Id check)
  4. Member's Level_Id is incremented by 1 (level upgraded)
  5. Record updated in DB
  6. Redirect to RegistrationIndex (new level view)
  7. Levels 1, 4, 7 are starting levels — no old members list shown for these

Flow 6 — Transaction Upload (by Member for Sub-Member)

Member GET /Home/TransactionCreate POST /Home/TransactionCreate

  1. After sub-member is registered, parent clicks Upload Transaction
  2. TransactionNCreate checks if transaction already exists for this member at this level
  3. Transaction form loads with Company Amount and Self (Help) Amount from Level table
  4. Parent enters: Company Transaction No, Self/Help Transaction No
  5. Parent uploads: Company receipt photo (IFormFile) + Member/Self receipt photo (IFormFile)
  6. POST validates both files and transaction numbers are non-empty and unique across DB
  7. Both images stored as VARBINARY in TblTransaction
  8. Upload path string constructed: Company_{TxNo}_{ParentId}_{MemberId}_{LevelId}_{FileName}
  9. Is_Approved = false, T_Date = DateTime.Now
  10. Record saved → Redirect to TransactionIndex

Flow 7 — Transaction Approval (by Super Admin)

Super Admin GET /Home/TransactionApprovalIndex POST /Home/TransactionApprovalEdit

  1. Super Admin sees full list of pending transactions at TransactionApprovalIndex
  2. Can filter by: Member name, Transaction No, Date range, Package name
  3. Clicks View Company Photo or View Member Photo to verify receipts
  4. Can Download receipt images via DownloadCompanyPhoto / DownloadMemberPhoto
  5. Clicks Edit/Approve → TransactionApprovalEdit view loads
  6. Super Admin sets Is_Approved = true + adds optional Note
  7. POST saves approval → Sub-member's Registration.Is_Active set to true
  8. Transaction list refreshed; approved transactions highlighted
  9. Level upgrade automatically evaluated for the parent

Flow 8 — Automatic Level Upgrade Logic

Member

  1. Level_Upgrade(Parent_Id, Level_Id, Package_ID) is called on every Login and Dashboard visit
  2. Checks: count of active sub-members at the current level for this parent == 0 (all promoted)
  3. Internally maps visual level: Levels 1–3 → 1–3; 4–6 → 1–3; 7–9 → 1–3 (3-tier display)
  4. If all members have moved up → ViewBag shows "🎉 Congratulations! Promoted to Next Level"
  5. Registration_Level_Upgrade(parent_id, Level_Id) controls whether Add Member button shows:
  6. Returns "true" if member slots still open (count < MemberCount)
  7. Returns "Pending" if slots filled but not all transactions approved
  8. Returns "false" if all slots filled and all transactions approved → member can proceed to next level

Flow 9 — PDF / Membership Slip Download

Member Admin

A) Personal Membership Slip downloadmembershipSlipSelf
  1. Loads member's Registration record
  2. Checks transaction approval status
  3. Generates PDF with: Sr.No (Package/Parent/Reg/Level), Name, Mobile, Username, Password, Status
  4. Returns PDF file download (A4)
B) Full Registration Form downloadmembershipSlip
  1. Loads member + Level details (amounts, branch fee)
  2. Shows Company bank details (A/c, IFSC, UPI) + Member bank details
  3. Shows QR code image
  4. Includes full T&C (6 clauses) + Signature line
  5. Returns PDF file download (A4)
C) Group Registration Slip downloadAllmembershipSlip — Lists all sub-members of a parent with their unique IDs in a table PDF.

Flow 10 — Admin Reports

Super Admin Admin

  1. Navigate to AdminAllMemberCashhInHandLevel view
  2. Report 1 — Adminpackage_NameReports: Total amount collected per Package
  3. Report 2 — Adminpackage_Name_Level_Reports: Amount per Package + Level
  4. Report 3 — Adminpackage_Name_Level_Name_Reports: Amount per Package + Level + Member Name
  5. All reports rendered as tables in the Admin layout
  6. Donation receipt can be generated via DonationReciept view

Flow 11 — Member Search

Member GET /Home/Search

  1. Member enters a Unique No (formatted as PackageName/ParentId/RegId/LevelId) in the search box
  2. GET request to /Home/Search?UserName=...
  3. DB queried: Registration WHERE Level_Id = currentLevel AND UserName = searchValue
  4. Results displayed in Search view
  5. If no input → Redirected to Index

1. UserLogin
-- =============================================
-- Table: UserLogin

CREATE TABLE UserLogin (
    id        INT            IDENTITY(1,1) PRIMARY KEY,
    UserName  NVARCHAR(MAX)  NOT NULL,
    passcode  NVARCHAR(MAX)  NOT NULL,
    isActive  INT            NOT NULL DEFAULT 0
);
2. Level
-- =============================================
-- Table: Level
-- =============================================
CREATE TABLE Level (
    Level_Id           INT              IDENTITY(1,1) PRIMARY KEY,
    Level_Name         NVARCHAR(200)    NOT NULL,
    Amount             DECIMAL(18,2)    NULL,
    Company_Percentage DECIMAL(18,2)    NULL,
    Self_Amount        DECIMAL(18,2)    NULL,
    Package_ID         INT              NOT NULL,
    Package_Name       NVARCHAR(200)    NOT NULL,
    MemberCount        INT              NOT NULL DEFAULT 0,
    Branchfee          INT              NOT NULL DEFAULT 0
);
3. Registration
-- =============================================
-- Table: Registration
-- =============================================
CREATE TABLE Registration (
    Reg_Id                   INT              IDENTITY(1,1) PRIMARY KEY,
    Full_Name                NVARCHAR(MAX)    NOT NULL,
    Mobile_No                DECIMAL(18,0)    NOT NULL,
    Bank_AC                  DECIMAL(18,0)    NULL,
    IFSC_Code                NVARCHAR(50)     NULL,
    UPI_ID                   NVARCHAR(100)    NULL,
    Password                 NVARCHAR(MAX)    NOT NULL,
    Term_Condition_Accepted  BIT              NOT NULL DEFAULT 0,
    Role                     NVARCHAR(50)     NULL,
    UserName                 NVARCHAR(MAX)    NOT NULL,
    Reg_Date                 DATETIME2        NOT NULL DEFAULT GETDATE(),
    Level_Id                 INT              NOT NULL DEFAULT 1,
    Parent_Id                INT              NOT NULL DEFAULT 0,
    Is_Active                BIT              NOT NULL DEFAULT 0,
    Package_ID               INT              NOT NULL DEFAULT 0,
    Package_Name             NVARCHAR(MAX)    NULL,
    CONSTRAINT FK_Registration_Level
        FOREIGN KEY (Level_Id) REFERENCES Level(Level_Id)
);
4. TblTransaction
-- =============================================
-- Table: TblTransaction
-- =============================================
CREATE TABLE TblTransaction (
    Transaction_ID                   INT              IDENTITY(1,1) PRIMARY KEY,
    Upload_Path                      NVARCHAR(MAX)    NOT NULL,
    Transaction_No                   NVARCHAR(200)    NOT NULL,
    Is_Approved                      BIT              NOT NULL DEFAULT 0,
    Reg_Id                           INT              NOT NULL,
    Level_Id                         INT              NOT NULL,
    Parent_Id                        INT              NOT NULL,
    Transaction_NoSelf               NVARCHAR(200)    NOT NULL,
    Upload_PathSelf                  NVARCHAR(MAX)    NOT NULL,
    Self_Amount                      DECIMAL(18,2)    NULL,
    Company_Percentage               DECIMAL(18,2)    NULL,
    T_Date                           DATETIME2        NULL,
    MemberTransactionPhoto           VARBINARY(MAX)   NULL,
    CompanyTransactionPhoto          VARBINARY(MAX)   NULL,
    CompanyTransactionPhotoContentType NVARCHAR(100)  NULL,
    MemberTransactionPhotoContentType  NVARCHAR(100)  NULL,
    Note                             NVARCHAR(MAX)    NULL,
    Package_ID                       INT              NOT NULL DEFAULT 0,
    Package_Name                     NVARCHAR(MAX)    NULL,
    CONSTRAINT FK_Transaction_Registration
        FOREIGN KEY (Reg_Id)    REFERENCES Registration(Reg_Id),
    CONSTRAINT FK_Transaction_Level
        FOREIGN KEY (Level_Id)  REFERENCES Level(Level_Id),
    CONSTRAINT FK_Transaction_Parent
        FOREIGN KEY (Parent_Id) REFERENCES Registration(Reg_Id)
);
